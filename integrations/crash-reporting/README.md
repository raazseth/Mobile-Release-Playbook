# Crash & Error Reporting Integration

This guide details the integration architecture, debug symbol upload mechanics (`.dSYM`, ProGuard/R8 mapping files), Hermes JavaScript stack trace de-obfuscation, and PII masking rules for **Crash & Monitoring Services** (Sentry, Firebase Crashlytics) in React Native and Expo applications.

It specifies how to capture production crashes and unhandled promise rejections while ensuring zero exposure of sensitive user credentials or PII.

This guide is **not**:

- an excuse to ignore production crash spikes
- a substitute for uploading debug symbols (`.dSYM`) during build compilation
- an authorization mechanism to log passwords, tokens, or personal user data to crash reporting servers

---

# 1. Integration Architecture & Symbolication Pipeline

Mobile applications compile code into native machine binaries (iOS arm64) and optimized bytecode (Android Hermes). Raw crash reports contain hex memory addresses or minified JS line numbers that must be **symbolicated** using build artifacts.

```text
[ Production Crash Event ]
            │
            ▼
[ Raw Hex Memory Stack Trace ]
            │
            ▼
┌────────────────────────────────────────────────────────┐
│             AUTOMATED SYMBOLICATION PIPELINE           │
│  - iOS: Match memory addresses against `.dSYM` files   │
│  - Android Native: Match stack trace to ProGuard map   │
│  - React Native JS: Match bundle index to Source Map  │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
[ Human-Readable Symbolicated Stack Trace in Sentry/Crashlytics ]
```

# 2. Uploading iOS Debug Symbols (`.dSYM`)

To symbolicate native iOS crashes in Sentry or Crashlytics, build pipelines must upload `.dSYM` debug symbol archives generated during compilation.

### Sentry EAS Build Configuration (`app.json`)

```json
{
  "expo": {
    "plugins": [
      [
        "@sentry/react-native/expo",
        {
          "organization": "YOUR_SENTRY_ORG",
          "project": "YOUR_SENTRY_PROJECT"
        }
      ]
    ]
  }
}
```

> **EAS Build Secret**: Ensure `SENTRY_AUTH_TOKEN` is configured as a build environment secret in EAS (`eas secret:create`) or CI secrets.

# 3. Android ProGuard / R8 & Hermes Source Maps

Android builds obfuscate Java/Kotlin code via R8 and compile JS into Hermes bytecode. Symbolication requires two mapping artifacts:

1. **`mapping.txt`**: Generated by R8 during `assembleRelease` (`android/app/build/outputs/mapping/release/mapping.txt`).
2. **Hermes Source Map**: Generated by Metro during JS bundle compilation (`index.android.bundle.map`).

```bash
# Sentry CLI Manual Upload Verification Command
npx @sentry/cli sourcemaps upload --org YOUR_ORG --project YOUR_PROJECT ./dist
```

# 4. PII Scrubbing & Event Sanitization

Crash reporting SDKs automatically capture network state, device models, and console logs. Configure `beforeSend` hooks to redact sensitive user data before transmission:

```javascript
import * as Sentry from '@sentry/react-native';

Sentry.init({
  dsn: 'https://YOUR_PUBLIC_KEY@sentry.io/YOUR_PROJECT_ID',
  beforeSend(event) {
    // Redact authorization headers and tokens
    if (event.request && event.request.headers) {
      delete event.request.headers['Authorization'];
    }

    // Mask user IP address
    if (event.user) {
      delete event.user.ip_address;
    }

    return event;
  },
});
```

# 5. Operational Verification Checklist

- [ ] **`.dSYM` Upload Verified**: iOS build artifacts automatically upload debug symbols during EAS Build / Fastlane.
- [ ] **ProGuard Mapping Uploaded**: Android R8 `mapping.txt` uploaded to crash reporting provider.
- [ ] **Hermes Source Maps Generated**: React Native Hermes JS bundle source maps generated and linked to release version string.
- [ ] **PII Redaction Active**: `beforeSend` hook redacts authorization tokens, passwords, and user IP addresses.
- [ ] **Test Crash Symbolicated**: Triggered test crash (`Sentry.nativeCrash()`) appears fully symbolicated in monitoring console.
